A essa altura você já sabe olhar um loop e dizer "isso é O(n)". Mas e
quando aparece um loop "esquisito" - que dobra o índice, que percorre só
até a metade, que tem um `if` dentro? Vamos às **regras práticas** que
resolvem 90% dos casos do dia a dia.

**Regra 1: um loop simples sobre n itens é O(n).**

```js
for (let i = 0; i < n; i++) {
  fazAlgo();              // 1 operação por iteração
}                         // total: O(n)
```

**Regra 2: loops em sequência somam; o maior vence.**

```js
for (let i = 0; i < n; i++) fazAlgo();   // O(n)
for (let i = 0; i < n; i++) fazAlgo2();  // O(n)
// Total: O(n) + O(n) = O(2n) = O(n)
```

**Regra 3: loops aninhados multiplicam.**

```js
for (let i = 0; i < n; i++) {           // O(n) vezes
  for (let j = 0; j < n; j++) {         // O(n) cada vez
    fazAlgo();                          // O(1)
  }
}                                       // Total: O(n * n) = O(n²)
```

**Regra 4: o índice muda, mas importa o "quanto sobra".**

```js
for (let i = 1; i < n; i *= 2) {        // dobra o i
  fazAlgo();
}
// Quantas iterações? O(log n) - porque i dobra até passar de n.
// Total: O(log n)
```

```js
for (let i = n; i > 1; i = Math.floor(i / 2)) {
  fazAlgo();
}
// Mesmo raciocínio: i cai pela metade → O(log n)
```

**Regra 5: o corpo do loop é a "unidade" - o que está dentro se repete.**

```js
for (let i = 0; i < n; i++) {           // O(n)
  if (lista[i] === alvo) return i;      // O(1) por iteração
}
// Total: O(n) - o if não muda a ordem de grandeza
```

**Regra 6: quebras antecipadas (`return`, `break`) só melhoram o caso
médio - o pior caso continua o mesmo.** Por isso a análise de complexidade
**fala do pior caso** por padrão.

```js
function procura(lista, alvo) {
  for (let i = 0; i < lista.length; i++) {
    if (lista[i] === alvo) return i;   // melhor caso: O(1)
  }                                    // pior caso (não achou): O(n)
  return -1;
}
// Análise: O(n) - porque o pior caso é o que importa pra Big O
```

**Regra 7: chamadas de função têm a complexidade delas.** Se dentro do
loop você chama uma função que é O(log n), o total vira O(n · log n) - é
o caso do `merge sort` e do `quick sort`, por exemplo.

> Dica: quando estiver em dúvida, **some as complexidades dos blocos em
> sequência** e **multiplique as complexidades dos blocos aninhados**.
> Depois, mantenha só o termo dominante. Esse é o processo mental que
> resolve quase todo código real.

- **Sequência soma, aninhamento multiplica.** É a regra que mais cai.
- **O índice determina quantas iterações:** `i++` é linear, `i *= 2` é
  logarítmico, `i += 2` ainda é linear (cabe O(n/2) = O(n)).
- **O pior caso vence.** Um `return` dentro do loop melhora a média, mas
  não muda a análise Big O.
- **Chamadas de função "carregam" a complexidade delas.** O(n) chamando
  O(log n) vira O(n log n).
