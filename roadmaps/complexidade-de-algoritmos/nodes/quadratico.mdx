Agora a "vilã" mais famosa da complexidade: a **quadrática**, O(n²).
Ela aparece sempre que, **para cada item** da sua lista, você **percorre a
lista de novo** - ou seja, um loop dentro de outro loop.

Exemplo clássico: comparar todos os pares possíveis de uma lista, para ver
quais são duplicados:

```js
function temDuplicados(lista) {
  for (let i = 0; i < lista.length; i++) {          // n vezes
    for (let j = 0; j < lista.length; j++) {        // n vezes para cada i
      if (i !== j && lista[i] === lista[j]) {
        return true;                                 // achou duplicado
      }
    }
  }
  return false;
}
```

Conte: o loop de fora roda `n` vezes, e para cada uma o de dentro roda
`n` vezes. Total: **n × n = n²** operações.

Outros exemplos de O(n²) que você vai encontrar:

- **Bubble Sort** - o algoritmo de ordenação "didático", simples mas lento.
- **Selection Sort** e **Insertion Sort** - outros dois simples, também O(n²).
- Comparar todos os pares (como no exemplo acima).
- Matrizes / tabelas: percorrer uma grade `n × n` para processar cada célula.

Por que O(n²) é "caro" na prática:

- 100 itens: 10.000 operações - ainda tranquilo.
- 1.000 itens: **1.000.000** de operações - já começa a doer.
- 10.000 itens: **100.000.000** de operações - pode levar **vários segundos**.
- 1.000.000 de itens: **1 trilhão** de operações - sem otimização, é
  inviável.

A boa notícia: a maioria dos problemas que parecem O(n²) tem uma solução
melhor. Por exemplo, aquele `temDuplicados` pode virar O(n) usando um
**Set** (que vamos ver mais pra frente na trilha):

```js
function temDuplicados(lista) {
  const vistos = new Set();
  for (const item of lista) {
    if (vistos.has(item)) return true;   // O(1) - já vimos?
    vistos.add(item);
  }
  return false;
}
```

- **O(n²) = quadrático.** Um loop dentro de outro: para cada item, faz algo
  com todos os outros.
- **Cresce rápido demais.** n² em 1.000 já é 1.000.000; em 10.000 é 100
  milhões. Acima disso, fica inviável sem otimização.
- **A boa notícia:** a maioria dos O(n²) "óbvios" tem alternativa melhor -
  vale a pena parar e pensar antes de implementar.

> Dica: se você se pegar escrevendo "para cada X, faça Y com todo o resto",
> pare e pergunte: "existe uma estrutura de dados que me dá essa resposta
> direto, sem percorrer tudo de novo?" Quase sempre tem.

Você conheceu o O(1), O(n) e O(n²) - a Santíssima Trindade do iniciante.
No próximo nó, vamos **formalizar** isso com a **notação Big O**, que é a
linguagem universal para descrever tudo isso.
