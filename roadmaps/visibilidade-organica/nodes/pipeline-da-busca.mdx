Entre a sua página e o primeiro resultado na tela existe uma máquina com quatro
etapas. Você não precisa saber o nome de cada algoritmo, mas precisa saber em
qual etapa a coisa quebrou — porque cada etapa tem um conserto diferente, e
otimizar a etapa errada é trabalho jogado fora.

## O essencial 🟢

**As quatro etapas.**

1. **Crawl (rastreamento).** O robô — o Googlebot, no caso do Google — segue
   links. Ele não "descobre" o site: ele percorre trilhas de links que já
   conhece. Se nada na web aponta para a página `/planos` da Aurora, o robô
   nunca chega até lá.
2. **Render (renderização).** O robô executa o JavaScript da página para ver
   o resultado final. Página que só existe depois do JS entra numa fila extra
   de renderização, e nem sempre sai dela.
3. **Index (indexação).** O que foi lido e considerado bom o bastante é
   guardado no índice.
4. **Rank (ranqueamento).** Na hora da busca, o motor ordena as páginas do
   índice para aquela consulta específica.

**O índice não é a web.** O índice é a cópia do Google: um recorte do que ele
conseguiu ver, organizado para consulta rápida. Tudo o que existe na internet e
nunca foi rastreado simplesmente não existe ali. E o inverso também vale: o
índice pode conter páginas que já foram apagadas do site, porque a remoção
leva tempo.

**Indexado não é ranqueado.** Estar no índice só garante que você é *candidato*.
A ordem é decidida por centenas de sinais, e relevância de texto é só um
deles.

```js
// Um "índice" simplificado: só entra o que foi rastreado E indexado.
const indice = new Map();

// Sinais usados no ranqueamento: relevância, autoridade e velocidade.
const sinais = {
  "https://aurora.app/planos": { relevancia: 0.9, autoridade: 0.6, velocidade: 0.4 },
  "https://exemplo.com/planilhas": { relevancia: 0.8, autoridade: 0.7, velocidade: 0.9 },
};

// Páginas que o Google indexou.
indice.set("https://aurora.app/planos", { titulo: "Planos da Aurora" });
indice.set("https://exemplo.com/planilhas", { titulo: "Planilhas grátis para equipes" });

// Ranqueamento: filtra o índice pela consulta e ordena pelos sinais.
function ranquear(consulta) {
  return [...indice.entries()]
    .filter(([, pagina]) => pagina.titulo.toLowerCase().includes(consulta.toLowerCase()))
    .map(([url]) => {
      const s = sinais[url];
      const score = s.relevancia * 0.6 + s.autoridade * 0.3 + s.velocidade * 0.1;
      return { url, score };
    })
    .sort((a, b) => b.score - a.score);
}

for (const resultado of ranquear("plan")) {
  console.log(resultado.url);
}
```

As duas páginas estão indexadas e as duas combinam com a busca. Mesmo assim a
que tem relevância maior (0,9) fica em segundo: os outros sinais pesam. E uma
terceira página, fora do índice, não aparece nem para ser considerada.

**Crawl budget, em um parágrafo.** O robô tem capacidade finita e um orçamento
de requisições. Em site pequeno, isso não é o seu problema. Em site grande —
catálogo com filtros, calendários, paginação, variações de URL — o orçamento
gasta em páginas que ninguém procura. Aí, cada URL inútil é uma página útil
que o robô não visitou.

**O que o crawler faz com links.** Só `<a href>` conta como link. Um `div` com
`onclick` não é link. Um botão que navega por JavaScript não é link. `rel="nofollow"`
faz o robô visitar a página, mas não repassa autoridade. E um `rel="canonical"`
aponta para a versão que o motor deve considerar a sua.

## Aprofundamento 🟡

**Renderização é fila, não garantia.** O Google separa o rastreamento da
renderização: a primeira leva o HTML bruto, a segunda executa o JavaScript.
Páginas com JS pesado ou dados que só chegam por API entram numa fila que pode
demorar. Se a fila está cheia, a página é indexada praticamente vazia — e é
assim que uma SPA "some" da busca sem dar erro nenhum.

**Soft 404: a página responde 200, mas não tem o que mostrar.** Se a sua rota
devolve HTML de app vazio com status 200 para qualquer endereço, o motor
indexa uma página sem conteúdo — várias, na verdade. Isso dilui o índice e faz
sua página real parecer rasa.

**O que o crawler descobre em um site inteiro.** Começando por uma raiz
conhecida, ele segue links, aplica os sinais que o impedem de seguir (noindex,
nofollow, canonical) e vai registrando o que viu. Páginas órfãs — sem nenhum
link interno apontando para elas e sem sitemap — são as que mais custam
caro: precisam ser adivinhadas ou anunciadas de fora.

> Atenção: um sitemap.xml não é um mapa do site para o robô. Ele é uma lista de
> URLs que você sugere para serem rastreadas. O robô continua decidindo o que
> seguir pelos links e o que indexar pela qualidade do que encontrar.

## Pra quem quer ir além 🔴

**Reproduzindo o crawl na sua máquina.** Você não precisa de ferramenta
paga para ver o que o robô enxerga. O `curl` mostra o HTML bruto que o
servidor devolve, que é exatamente o ponto de partida do rastreamento:

```bash
# HTML bruto da home: é o que o Googlebot recebe antes de rodar qualquer JS
curl -s https://seudominio.com/ | head -40

# Só os links que o robô conseguiria seguir a partir dessa página
curl -s https://seudominio.com/ | grep -o 'href="[^"]*"' | head -20
```

Se a segunda lista vier curta e o seu site tem muitas páginas, o problema
está na malha de links internos — não no conteúdo.

**O que decide o que fica no índice.** Depois de renderizar, o motor avalia
qualidade, unicidade e sinais do site inteiro. Páginas quase idênticas entre
si, sem autoridade, ou que já existam em versão melhor na web tendem a ficar
de fora do índice. É por isso que "publicar mais" costuma render menos do que
"publicar uma coisa que ainda não existe".

## No seu projeto

- [ ] Abra o código-fonte da sua home (view-source, ou `curl` no terminal) e
  liste as URLs que um robô conseguiria seguir a partir dela. Se alguma página
  importante não está na lista, ela está órfã: resolva antes de escrever
  qualquer conteúdo novo.
- [ ] Escolha a rota mais importante do seu site e verifique se o conteúdo
  principal já está no HTML inicial ou só aparece depois que o JavaScript roda.
  Se só aparece depois, anote isso: é a causa número um de página indexada
  vazia.
