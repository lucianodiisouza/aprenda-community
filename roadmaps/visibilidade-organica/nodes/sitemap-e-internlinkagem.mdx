O sitemap diz ao buscador que uma página existe. A malha de links internos diz
por que essa página deveria importar. São duas ferramentas complementares: a
primeira resolve as páginas órfãs, a segunda distribui autoridade.

## O essencial 🟢

Um `sitemap.xml` é uma lista de URLs do seu site. Só isso:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://seusite.com/</loc>
    <lastmod>2026-01-10</lastmod>
    <priority>1.0</priority>
  </url>
  <url>
    <loc>https://seusite.com/blog</loc>
    <lastmod>2026-02-01</lastmod>
    <priority>0.8</priority>
  </url>
</urlset>
```

Ele fica na raiz do site (`https://seusite.com/sitemap.xml`) e o
`robots.txt` aponta pra ele:

```text
User-agent: *
Disallow: /admin
Sitemap: https://seusite.com/sitemap.xml
```

O que o sitemap **faz**: diz ao crawler "existem essas páginas". Ele acelera a
descoberta de conteúdo novo e, principalmente, **denuncia as páginas órfãs** —
aquelas que ninguém linka, nem de fora nem de dentro do site.

O que o sitemap **não** faz:

- Não garante indexação. Quem decide isso é o `canonical` e o `meta robots`.
- Não obriga o crawler a visitar. Ele prioriza links.
- Não substitui links internos. Uma página listada no sitemap e sem nenhum
  link apontando para ela continua fraca.

E o `<lastmod>` precisa ser honesto. Ele existe para dizer "isto mudou de
verdade". Se todo deploy reescrevesse a data de hoje, você estaria
ensinando o crawler a ignorar o campo — é o "profeta do mal" do SEO técnico.
A data tem que vir do seu histórico (último commit que mexeu na página, data
de publicação real), não de `new Date()`.

O outro lado da moeda é a malha interna. Um link interno é um `<a href>` de
verdade:

```html
<nav>
  <a href="/blog/sprints-remotas">Guia de sprints para equipes remotas</a>
  <a href="/blog/retrospectiva">Como fazer retrospectiva remota</a>
</nav>
```

O texto do link (`Guia de sprints para equipes remotas`) é o que diz ao
buscador **do que fala a página de destino**. É a única forma de você
controlar o assunto sobre o qual aquela URL é indexada. "Clique aqui" não
serve para nada.

O que você fixa daqui:

- Sitemap = lista de URLs; não controla indexação.
- `lastmod` honesto muda a data só quando o conteúdo muda.
- Link interno é `<a href>` com texto descritivo.

A malha ideal não é uma árvore nem um grafo todo ligado: é **hub-and-spoke**.
Uma página pilar (o hub) recebe links de todas as páginas de apoio (os
spokes), e cada página de apoio aponta de volta para o hub e para o CTA.
Isso faz duas coisas ao mesmo tempo: distribui autoridade para as páginas que
interessa e cria caminhos de volta para a conversão.

Regras práticas de malha:

- **Profundidade.** Toda página importante deve estar a até 3 cliques da home.
  Passou disso, ela quase não recebe sinal.
- **Âncora descritiva.** O texto do link diz o assunto da página de destino.
  Evite "clique aqui", "saiba mais" e "leia".
- **Links de verdade.** Navegação por `onclick` sem `href` não é link — o
  crawler não segue (você vai ver isso em detalhe no nó `javascript-seo`).
- **Sem páginas órfãs.** Cada URL publicada deveria receber pelo menos um link
  interno. Ou entra no sitemap, ou entra na malha. Idealmente, os dois.

E um detalhe sobre o sitemap que costuma passar batido: ele não é uma lista de
prioridades para o Google, é um índice de existência. O Google inclusive
ignora as tags `<priority>` e `<changefreq>` — o que sobra é o `<loc>` e o
`<lastmod>`. Outro detalhe: o `<lastmod>` só deve mudar quando o **conteúdo**
muda, não quando você mexe no CSS.

## Pra quem quer ir além 🔴

Limites práticos: um arquivo de sitemap suporta 50.000 URLs e 50 MB (sem
compressão). Passando disso, você divide em vários arquivos e aponta para
eles com um **sitemap índice**, que é um sitemap que só lista outros
sitemaps:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap>
    <loc>https://seusite.com/sitemap-blog.xml</loc>
  </sitemap>
  <sitemap>
    <loc>https://seusite.com/sitemap-produtos.xml</loc>
  </sitemap>
</sitemapindex>
```

Existe ainda o **sitemap de imagens**, que aponta para arquivos de imagem
(você também pode declarar as imagens dentro do sitemap normal, com a tag
`<image:image>`). Ele é a forma de você dizer ao Google "esta imagem faz
parte desta página", em vez de deixar o buscador adivinhar.

E uma armadilha de operações: **tirar a página do sitemap não a tira do
índice**. Ela pode continuar indexada se tiver links apontando para ela. Para
remover, o caminho é `noindex` (que você já viu) ou `301` para outra página.

Por fim, o relatório de sitemaps no Search Console mostra o que o Google
achou: quantas URLs você mandou, quantas ele leu, quantas foram indexadas e
quais ele ignorou. É o lugar para descobrir que você listou 800 URLs e 300
delas retornam 404.

## No seu projeto

- [ ] Gere o `sitemap.xml` do seu site a partir das rotas reais (você pode adaptar o código do checkpoint) e confira se ele lista só as URLs que você quer que existam.
- [ ] Abra a página mais importante do seu projeto e conte quantos links internos apontam para ela. Se a conta for zero, ela está órfã: linke a partir de outra página.

> Atenção: confira se toda página do sitemap responde 200. Uma lista com 30% de
> URLs quebradas faz o crawler gastar visita com erro e passa a passar um sinal
> ruim sobre a saúde do seu site.

## Fechamento

Você já controla o que o crawler visita e o que ele indexa. No próximo nó você
ataca o que a pessoa **sente** ao chegar: a velocidade e a estabilidade da
página, que o Google também usa como sinal.
