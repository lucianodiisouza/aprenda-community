Antes de discutir arquitetura, você precisa conseguir criar e rodar um app. No
Angular, esse caminho passa pelo Angular CLI.

O CLI é a ferramenta que cria o projeto, sobe servidor local, gera arquivos,
roda build e aciona testes. Ele evita que cada pessoa monte a estrutura do zero
de um jeito diferente.

```bash
npm install -g @angular/cli
ng new meu-app
cd meu-app
ng serve
```

Depois disso, o app fica disponível no navegador. A partir daí você edita os
arquivos em `src/` e vê a tela recarregar durante o desenvolvimento.

## O que está acontecendo

`ng new` cria um workspace com TypeScript, build, assets, configuração de teste e
um primeiro componente. `ng serve` inicia o servidor local. `ng generate` cria
peças novas no padrão do framework.

```bash
ng generate component trilhas
ng generate service trilhas
```

Três coisas pra levar deste nó:

- **Use o CLI enquanto aprende.** Ele reduz erro de nome, pasta e import.
- **`ng serve` é para desenvolvimento**, não para publicar o app.
- **`ng build` gera a versão de produção**, que será servida por outra camada.

> Dica: se um tutorial manda criar muitos arquivos na mão, tente descobrir o
> comando `ng generate` equivalente. Em projeto real, consistência vale muito.
